# 求职投递台 · 公开规格

此文件定义公开版的现行行为，不包含个人求职档案、真实 JD 案例或内部验收记录。`evidence` 是新用户默认匹配方式；未声明 `match_engine` 或显式 `blocks` 的配置使用旧版兼容方式。二者不混算。

## 0. 目标与边界

将本地岗位信息、人工确认的经历和可解释的匹配依据放入静态投递台。使用者自己选择岗位和完成投递。工具不代投、不定时运行，也不自动决定停止招聘。

## 1. 初始化

与使用者确认城市、岗位方向、可用模型和来源。先读取已有材料，只问缺口和矛盾。标题排除词与保护词须从岗位样本归纳后由使用者确认；模型不代选个人意向。

## 2. 筛选与去重

管道硬排除只采用配置明确给出的条件，并将排除结果与原因保存到 `_excluded.json`。公司规模用可撤销的视图折叠控制。去重按公司、归一化标题和城市保守合并；模糊相似仅标记。

## 3. 多方向与共享状态

共享的 `store.json`、`state.json`、`taxonomy.json`、`company_intel.json` 放在主配置目录。每个方向有独立偏好、画像和输出，`--track` 必须贯穿各阶段。相同岗位不因搜索词改变而成为新的投递对象。

## 4. 关键词

搜索词用于抓取；展示词与相关性词用于解释和公司信息分析。关键词命中数量不作为岗位是否保留的语义闸门。岗位方向词汇和路径必须来自配置。

## 5. 标题闸门

只排除明确的其他职业，不依据标题肯定目标职业。排除词和保护词同时命中时先放行，交给完整职责判读。两个列表为空时明确告知闸门不生效。

## 6. 文本归一与切块

先调用 `chunker.normalize()` 处理兼容汉字、康熙部首、零宽字符和不换行空格，保留中文标点。按职责、要求、加分、福利和公司介绍等分段，再分条。无法可靠划分的内容保留并标记，不能仅依据比例判否。

## 7. 职责判定

职责块标记 `是` / `否` / `说不好` / `非职责`，同时标记职能族。判断产出物而不是工具：相同工具可以服务不同职能。

有效分母为“是 + 否”；小于 3 时退回整篇判读。有效比例小于 0.50 判否，0.50 至小于 0.65 保留并提示职责偏离。说不好超过一半或非职责超过 0.30 时退回整篇核对。初始阈值不等于真实市场准确率。

## 8. 方向和类目

二级方向采用技术、用户和职能等轴的多标签。标签可提议新增，不能自动合并人类定义。职责、硬技能、软技能、工具栈、赛道、专业背景与产品形态参与兼容匹配；反门槛、福利和公司介绍分别展示。

## 9. 配置与数据目录

所有运行路径相对 `config.json` 目录解析。模板位于 `templates/`；实际配置和数据应放在独立的个人工作目录。

| 字段 | 含义 |
|---|---|
| `cities`、`target_role`、`role_aliases` | 本人确认的城市、目标岗位与别称 |
| `hard_exclude` | 明确的排除条件，保留排除记录 |
| `title_gate` | 标题开关、排除词和保护词 |
| `keywords` | 用于展示与相关性分析的词，不按命中数筛选 |
| `judge.model` | 实际判读宿主可用且由使用者选择的模型标识 |
| `judge.task_models` | market/interview/requirements/resume 的可选模型覆盖 |
| `judge.reasoning_effort` | 宿主支持时采用的任务参数；改变后需重审旧任务 |
| `scoring.match_engine` | `evidence` 或兼容的 `blocks` |
| `scoring.blend` | 公司分和匹配分的可选混合展示权重 |
| `crawl` | 可选抓取脚本路径、搜索词、筛选码和单轮上限 |
| `evidence` | 档案路径、工作区和显式来源；契约见 §21.2 |
| `resume_editor` | 初始栏目、求职意向展示与编辑器配置 |
| `output_dir`、`taxonomy_path` | 输出与词表路径 |

脚本不直接调用模型服务。模型在宿主中读取任务包，脚本再验证结果；未配置模型时拒绝生成需要模型的任务。

## 10. 兼容的块匹配

匹配分为 `100 × Σ(命中块权重) / Σ(计分块权重)`。命中为 1，部分命中为 0.5，未命中为 0；必须说明对应的经历。软技能初始权重为 0.3，加分段乘 0.5。没有 `evidence` 匹配结果时，不把旧关键词分冒充新版匹配率。

## 11. 门槛与薪资

学历、在读身份、地点和出勤等条件单独供本人检查；薪资不进入能力分。现行规则不采用旧模板的门槛扣分。反门槛可以显示为标签，并按配置对混合排序加分，不改变能力匹配分。

## 12. 词表维护

按归一化要点统计频率。每三轮抓取或累计新增超过二十个要点时，交人检查疑似同义项。脚本可提出候选对，不能自行改变概念定义。

## 13. 现场屏蔽

只有使用者操作才能记录不感兴趣、屏蔽公司或行业。已投递记录保持可见；屏蔽可撤销，视图折叠不等于删除数据。

## 14. 静态投递台

列表按使用时机展示状态、岗位、公司、薪资、地点和来源入口；匹配有结果才显示，未知与零分区分。详情包含依据、缺口、来源与原文，空内容不显示。

四态为 `待定`、`不感兴趣`、`已投递`、`停止招聘`；独立记录看过标记。改变状态或筛选不重排岗位节点，只有显式排序可以重排。页面不加载外部脚本、样式或字体，无定时器、后台请求和自动跳转。用户主动打开来源链接不属于后台请求。

## 15. 抓取控制

只人工触发，一轮后停止并诊断。列表可更新，详情仅处理本地缺少内容的岗位。补抓须本人批准，仅限缺失 ID，最多一轮；禁止自动全量重试。风控码 31/37、访问频繁、环境异常或登录失效立即停止。

岗位长时间未出现只是提示，不能由脚本据此修改投递状态。外部抓取器单独安装并配置，公开仓库不分发其源码、历史或本机登录态。

## 16. 公司信息

本地信号与外部情报分开记录，外部结果按公司缓存，包括查不到的情况。没有证据时显示情报不足，不能凭推测补齐。

## 17. 验证

确定性测试使用虚构数据和临时目录。测试通过不等于真实 JD 的语义判读已经正确，也不等于真实求职结果或业务验收。独立验证页面交互、来源完整性和个人简历措辞。

## 18. 成本记录

记录任务包大小、缓存命中和阶段耗时。字符数不是 token 用量，估算不是真实账单；不发布缺少采集依据的价格或费用结论。

## 19. 已知限制

岗位样本不是市场全集，招聘状态需要本人核对；标题和职责规则可能遇到边界案例。词表需人工维护，不做跨网站身份归并。大规模存储需要另行评估，不能把小样例性能外推为容量保证。

## 20. 公开分发边界

仓库只分发代码、通用规则和明确虚构的样例。个人档案、真实岗位库、日志、投递状态、来源材料与生成的个人简历不属于公开内容。对自有材料的事实确认与对外发布授权是不同的动作。


## 21. 经历驱动匹配与针对性简历

### 21.1 流程与模型边界

简短意向收集 → 一轮岗位样本（目标约 100 条，不是市场全集）→ 提炼能力目录 → 导入已有材料并围绕事件逐轮访谈 → 确认经历档案 → 匹配 → 选定岗位 → 调整简历 → 检查 PDF。已有材料优先复用，只追问缺口、矛盾与新要求。基础访谈不是压力面试。

模型负责语义提取、能力映射、新场景判断和简历措辞；脚本负责引用校验、去重、缓存、计分与排版。仍沿用文件任务包边界和 `judge.model`，不在脚本中直接调用模型。模型未配置时任务生成明确报错；不影响本地模板、来源登记及确定性测试。


### 21.2 数据契约（schema_version = 1）

所有新增路径相对 config 目录解析，统一放在配置 `evidence` 对象：`catalog_path`、`profile_path`、`requirements_path`、`workspace_dir`、`source_files`（显式文件数组，不扫描无关个人文件）。配置不填时前三项分别用 `./evidence/capabilities.json`、`./evidence/profile.json`、`./evidence/requirements.json`，工作区用 `./evidence`。新输出与旧 `out/judge/manifest.json` 隔离。

- 能力目录：`{schema_version, version, modules:[{id,name,weight,criteria:[{id,name,anchors}]}]}`。criterion id 全局唯一；anchors 是 5 条字符串，对应 0 无法完成、1 知道/理解、2 有参与实践、3 独立完成、4 在明确条件下稳定完成。具体判据由每项能力给出，不按经历数量升级。模块 weight 为正数，作为总分预算；只对 JD 涉及模块归一到 100。
- 经历档案：`{schema_version, candidate:{}, sources:[{id,path,sha256}], experiences:[{id,title,organization,period,role,facts:[{id,text,status,sources:[{source_id,start_line,end_line,quote}]}]}], assessments:[{criterion_id,context,level,status,fact_ids,reason}]}`。status 为 `confirmed/pending/disputed`，level 为 0..4 或 null。来源为 UTF-8 文本，行号从 1 开始，quote 必须与指定整行片段相同（换行统一）；路径相对 config。新能力评定不能偷偷改变事实确认状态。
- 经历事实与能力评定分开；同一事实可支持多个判断项；同一事件多处引用仍是一件事。confirmed 是用户确认后的记录状态，不意味着自动获得外部成果验证；实践边界写进 fact.text 和 assessment.reason。原文/哈希不符必须拒绝继续应用，不能静默打零。
- fact 可选 `kind=evidence/boundary`，默认 evidence。boundary 表示本人确认的责任、上线或验证边界，与普通事实使用同样的确认与来源校验。选中相关经历写简历时，需同时提供该经历全部 confirmed boundary，避免只筛出能力证明而丢掉自用/无外部验证等限制。
- JD 要求：`{schema_version, jobs:[{job_id,jd_hash,requirements:[{id,module_id,text,source_quote,importance,critical,mode,criteria:[{criterion_id,required_level,context}]}]}]}`。jd_hash 为规范化 JD 的 SHA256；source_quote 必须能在规范化 JD 中定位。importance 为 `required/preferred`，权重默认 1/0.5；critical 为布尔；mode 为 `all/any`；required_level 为 1..4；context 为严格匹配的场景字符串，空字符串只代表无额外场景要求。不把通用能力默认为专业场景能力。
- 非能力条件：岗位记录可含 `conditions:[{id,type,text,source_quote,importance,critical}]`，保存学历、在读身份、到岗天数/月份、地点、证书、作品材料等非能力条件。字段类型与引用校验沿用要求规则，type 为非空分类字符串。它们不套用能力等级、不进入评分，详情单独展示供本人核对；不自动推断符合或不符合。公司介绍、薪资和福利不列入条件。旧记录缺省为空数组。
- 真实目录无法准确表达的能力保存在可选 `unmapped_requirements:[{id,text,source_quote,importance}]`，引用非空且连续；不能挤入近似能力、丢弃或混成学历条件。存在任何未映射能力时，完整总分、上下界与覆盖率均为 null，保留已映射部分的模块依据并明确其范围。列表显示「要求待完善」，详情列出缺口。仅含未映射能力的岗位也可保存，未知不能记零。目录后续完善后重新核验映射再恢复完整评分。
- 同一岗位相同 module、mode、criteria（含水平与场景）为同一计分要求，重复引用合并，importance 取较高、critical 取 OR。模型需将语义同义项映射为相同标准 ID，程序不假装能识别任意同义句。
- 真实样本发现跨模块替代（如 Python 或可视化工具）。any 可引用不同模块的能力，要求仅归属候选模块中目录顺序最靠前的一个模块并计分一次，不因分支数增加预算；交换分支顺序不改变归属。all 仍在一个模块内，跨模块同时必需能力拆为独立要求。不能仅保留替代关系的一条分支。

### 21.3 评分与未知

confirmed 评定且 fact_ids 全部存在、confirmed、引用有效才可计入。pending/disputed 和没有记录均是未知，不能当 0。明确不能完成可以有 confirmed level=0，但仍须引用访谈事实。相同能力/场景的多份已确认评定取最高有证据等级，不累加；若该能力/场景有 disputed 评定，则整个判断为未知，不能绕过争议取旧高分。pending 新材料本身不推翻已有 confirmed 判断；发现冲突必须明确改为 disputed。禁止数量投票。

单项满足度 = min(能力等级 / 要求等级, 1)。这是第一版可解释的排序规则，不是经验测得的能力概率。all 取最弱项（整体要求必须同时成立）；any 取最强项（替代方案满足一个即可）。需要同一事件端到端责任时，应定义单独的完整流程 criterion，不能拼接多个局部参与经历冒充独立负责。

同模块、同场景、同一组 all 能力重复要求时，同一必需/优先类别只保留各能力的最高门槛，合并所有原文引用；重复一个更弱门槛不能提高分数。必需门槛已覆盖的较弱优先项不另分预算；更高的优先门槛独立保留，不能把优先的高等级强行升成必需。any 的不同门槛组合不直接取最高等级合并，以免改变替代逻辑。

模块内按去重要求及 importance 求加权满足度，最高 100%；模块之间按 catalog weight 归一。每个模块显示实际得分与该 JD 下的上限。核心缺口独立列出，不自动排除岗位，也不能被其他模块高分隐藏。


未知项计算上下界：未知满足度区间 [0,1]，已确认不足为确定值。只有总分上下界相等时 score 才有数值，否则 score=null，显示“待补充”与可展开范围。下界只是已证实覆盖，不是宣称未知能力为零；不直接按未知下界排名。coverage 记录已判定要求的加权占比。

多段经历补齐不同判断项可以提高覆盖；相同环节的重复经历用于支持“稳定完成”判据，不能直接奖励加分。不采用经历次数衰减系数，不引入强化学习。

### 21.4 缓存与引用

JD 提取缓存依赖规范化 JD 内容、完整目录内容及提取规则版本，不能只依赖 job_id 或标签；经历变化不重读 JD。确定性评分每次从当前档案重算（无模型成本）。同一标准能力/场景的评定跨岗位复用；场景/等级的新判断需产生新的任务，不能按名称随意复用。

同一 JD 内容换岗位 ID 可复用已有已校验要求；不同措辞的语义归一仍由模型完成。目录里的既有能力 ID 不允许原地更换含义或等级锚点，新定义使用新 ID，避免旧能力评定被静默重新解释。每轮访谈建议保存独立原文文件；已入库原文如被改写，先核对相关引用并更新版本，再继续判读，程序不自动重置旧哈希。

来源按显式名单登记，保留原始文件、内容哈希、行号与原话。材料改动、矛盾或确认状态变化时需重审相关判断。模型生成的好评或改写建议不能作为已发生事实。先不引入向量数据库；记录任务大小与缓存命中，不把字符数冒充实际 token 消耗。

首次整理长材料可用 `interview-task --all-sources`：按字符预算和完整行生成多个包，每个工作者只读一个包；manifest 记录全部来源片段，合并为完整档案后一次 apply。后续实际访谈沿用默认小轮次。局部包不能冒充全部来源完成，不能随判读自动确认事实。

### 21.5 简历

选定 job_id 后，仅提供相关 confirmed 事实及 JD 给写作任务，不为全部岗位提前生成简历。写作结果为 `{schema_version,job_id,profile_hash,jd_hash,task_hash,headline,sections:[{title,items:[{text,fact_ids}]}]}`；candidate 展示字段来自档案，正文每条必须引用本次任务允许的事实。程序验证引用存在、状态、来源和输入哈希，但不声称引用存在就证明改写语义正确；措辞、归属、数字仍需内容审阅。

导出可编辑 Markdown、引用审阅记录与 PDF 草稿；不写模型分数、证据 ID 或内部状态进简历正文。实际个人成稿依赖用户确认的事实；隔离虚构样例只用于排版/链路验证，不能称为个人简历交付。不得杜撰经历、指标、学历或责任，不自动投递。

### 21.6 上线验收

必须覆盖：重复要求和重复证据不涨分；互补证据增加覆盖；AND/OR；具体场景不误复用；无证据/有争议不记 0；明确不具备才为 0；核心缺口保留；来源修改拒绝旧评定；JD 与目录变化失效；画像变化不迫使重新提取相同 JD；无效/缺失结果不能当完成；中文 PDF 页面无溢出；旧任务、岗位数据、人工状态不被改写。

### 21.7 可编辑简历与参考版式


投递台生成同目录 `简历编辑器.html` 并提供入口。静态编辑器支持任意文字行、三栏经历行、局部加粗／斜体／下划线／黑灰文字、对齐、字块／行／栏目／经历删除、整条经历及整栏目顺序调整、撤销重做、栏目隐藏与另起一页；调节字号、行距、页边距及栏目／行间距。`resume_editor.show_intent` 控制初始求职意向显示，默认 false；初始栏目标题由 `resume_editor.section_titles` 配置，不硬编码个人经历。删除空字块与隐藏求职意向不进入打印稿。

编辑器纯本地，不发网络请求、无定时器，不写投递状态或经历档案。改动以独立 `resume_editor_v1:<document_id>` 保存在浏览器；本地保存失败必须明确提示，可下载自包含 HTML 草稿备份、再打开或导入继续编辑。导入先校验完整结构并清理 HTML，仅保留文字与有限格式；失败不替换当前稿。

PDF 由用户点击“导出 PDF”调用浏览器打印，选择另存为 PDF、A4、100% 缩放并关闭页眉页脚。打印 CSS 使用 A4、可选页边距、自动分页与栏目手工分页，不打印工具栏、空白提示或内部引用。长正文允许跨页，栏目标题尽量与后续内容同页。编辑器不是任意 PDF 反向编辑器，不自动解析参考 PDF 到字段。

选岗后的 `resume_export.py export` 继续校验来源／事实／任务哈希，额外生成 `resume-editor.html`，嵌入原始 result 和 review 供追溯；既有 Markdown／review／PDF 保留。手工改写仍标记 `manual_draft_requires_content_review`，不冒充引用已校验或本人已确认，不写回 profile。CLI PDF 默认隐藏求职意向、姓名与联系信息居中、栏目左对齐；最终自由排版以编辑器打印为准。用户手工添加的教育、公司或新成果不被自动加入 evidence 档案。

验收覆盖：字块删除、局部格式、文字追加、整栏目／经历移动、隐藏／恢复、撤销、刷新、备份重开／导入、坏文件不覆盖、旧投递状态不变、零网络请求、A4 中文 PDF 可选中文本与多页分页，结果与用户最终内容验收分别报告。
